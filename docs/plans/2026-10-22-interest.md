# phro-trend 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `interest` skill, feed its interests into `weekly`, let `weekly` and `ai` write up to 10 stories and papers, pre-filter `collect` by popularity, and rewrite the skill instructions in English.

**Architecture:** `skills/interest/scripts/interest.py` turns session records and recent documents into a small text input, Claude writes the interests, and the script stores them in `interests.json`. `weekly.py collect` reads the stored keywords for its pre-filter; the two skills share only that file. `check.py` caps scale with the story count.

**Tech Stack:** Python 3.9+ standard library, `unittest`.

**Spec:** `docs/specs/2026-10-22-interest-design.md`

## Global Constraints

- Standard library only. Scripts run as `python -I`, start with `from __future__ import annotations`, call `sys.stdout.reconfigure(encoding="utf-8")` in `__main__`, and use no syntax newer than 3.9.
- Record home `~/.claude/phro-trend` (`--home` overrides). Claude dir `CLAUDE_CONFIG_DIR` when set, else `~/.claude` (`--claude-dir` overrides).
- Window 14 days. Input at most 10,000 characters: sessions 7,000 in equal shares, documents 3,000. Prompts cut to 160 characters, newest 8 per session. Summary: 600 characters after the `Summary:` line. Documents at most 2 MB, at most 60 lines, a folder with more than 20 matching files folds into one line.
- Interests: 5 to 8; `topic` at most 40 characters; `keywords` 2 to 5, none generic; `why` at most 120 characters.
- Stories and papers: 1 to 10. Body cap 2,000 + 1,000 per core story. Pre-filter: top quarter of a scored source, all kept below 20 scored stories, match section at most 30 rows.
- Language: instructions, spec, plan and `interest.py` messages are English. `weekly.py` and `check.py` messages stay Korean, new ones included. Korean output strings never change.
- Commits: `git -C <repo> -c user.name=thatshoon -c user.email=gagea45@gmail.com commit`, no AI attribution lines. No em or en dashes in docs or pages.
- Test command: `python -I -m unittest discover -s <repo>/tests -t <repo>` (add `-p test_x.py` for one file).

## Review Focus

1. Record lines with invalid UTF-8 bytes: the reader replaces them and keeps going. Test in Task 1.
2. The same project spelled with another case or slash style on Windows: same sessions, same store key. Tests in Tasks 1 and 3.
3. Generic keywords ("AI", "LLM", "모델") would rescue every story and void the pre-filter: `save` rejects them. Test in Task 3.
4. The ISO week at year end (2027-01-01 is 2026-W53): freshness must not flip early. Test in Task 3.
5. Older records whose entries carry no `cwd`: kept only in the exact-name folder, skipped in lookalike folders. Test in Task 1.
